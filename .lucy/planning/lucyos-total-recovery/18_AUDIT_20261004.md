## 7. New issues found by this audit
- **ISSUE-045:** the status column of `work_orders/INDEX.md` and some `04_` statuses (ISSUE-013) lagged behind merged work, so agents read stale status. Fixed in this PR. The rule going forward is in `19_` §6: whoever finishes an order updates its status cell in the same PR.
- **ISSUE-046:** agent sessions cannot push tags, delete remote branches, or create refs through the API (refused 2026-10-04: `git push` disconnect, API 403). TR-0-06 and all archive tagging are therefore **owner-run scripts**. Agents prepare the commands.
- **ISSUE-047:** the critical path depends on overrides that nobody has been asked to record. Fixed by adding an "override batch" step to TR-0-03 (`19_` §3, step F1).

- **ISSUE-048:** `backup.create()` with `BACKUP_PASSPHRASE` set writes the plaintext tar.gz (DB snapshot and memory) to `BACKUPS/` and only then overwrites it with ciphertext. The module docstring claims the archive "is encrypted before it touches disk". Low severity (secrets are excluded, and it is the same file on the same disk), but the claim is false and a crash mid-way leaves plaintext. Fixed by TR-2-06 step 2 (encrypt in memory).
