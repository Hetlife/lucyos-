# TR-1-03 — Governed `whatsapp` verb on the OpenClaw bridge

**Why:** The owner cannot approve/deny/pause through OpenClaw; the bridge exposes read verbs only (ISSUE-011). This is the single edge that turns LucyOS operable from the phone.
**Current evidence:** EV-OPENCLAW-PATH; `aion whatsapp` (cli.py:118 -> `router.handle`), `integrations/openclaw/lucyos/scripts/lucyosctl`, `lucyos-remote-dispatch` (SIMPLE dict, ATOM/TASK_ID regexes), `tests/test_openclaw_lucyos_bridge.py`
**Executor:** CLAUDE_CODE
**Scope:** `integrations/openclaw/lucyos/scripts/lucyosctl` (+`whatsapp "<text>"`), `integrations/openclaw/lucyos/scripts/lucyos-remote-dispatch` (+`whatsapp` with 512-byte cap, printable-ASCII/UTF-8 check, no newlines), `integrations/openclaw/lucyos/SKILL.md` (document the verb and that OpenClaw must pass the sender's WhatsApp id as `LUCYOS_PRINCIPAL`), `aion_core/cli.py` `whatsapp` subcommand gains `--principal <id>` and `--channel openclaw` which are logged via `db.log_event('whatsapp','openclaw',...)` (never in the message), tests
**Do not touch:** `.lucy/authority/**`, `scripts/verify_authority.py`, `.github/workflows/lucyos-ci.yml`, any protected path without a recorded override; no new third-party dependency; no new `aion_core` module; do not touch `router.py`/`approvals.py` (protected): the verb must reuse `router.handle` unchanged; do not add a new HTTP server
**Dependencies:** none

## Steps
1. Read `router.handle` and the existing `whatsapp` CLI path; confirm `security.redact` runs on input and output.
2. Add the verb to both scripts mirroring the `context` pattern (strict argument validation; forced command never sees a shell).
3. Add `--principal/--channel` to the CLI and log one event per message with principal, channel, key id (`SSH_ORIGINAL_COMMAND` caller key fingerprint if available via `SSH_USER_AUTH`/`LUCYOS_KEY_ID` env), and the redacted verb (first word only).
4. Tests: local dispatch of `status`; `approve A-1` transitions an approval; oversize / newline / control chars refused with exit 2; event row carries principal and never the message body; remote dispatcher refuses `whatsapp` with two args.
5. Update SKILL.md preflight: approvals now go through `lucyosctl whatsapp`.
