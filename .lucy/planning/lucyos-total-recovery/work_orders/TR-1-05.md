# TR-1-05 — Live E2E: owner WhatsApp -> OpenClaw -> LucyOS approval, attributed

**Why:** L2 requires observed proof that an owner decision sent from the phone through OpenClaw changes canonical state and is attributed to the sender.
**Current evidence:** PR #89 (TR-1-03) merged: `lucyosctl whatsapp` exists on main. Branch `fable/router-strict-approvals` makes only the exact `APPROVE <ID>` / `DENY <ID>` form decide (loose phrases such as "don't approve A-1" used to approve). `aion audit-export` records `actor=openclaw:<sender id>` on the bridge message and on the decision (verified in a temp brain, 2026-09-30).
**Executor:** OWNER (steps 1, 3, 5 on the Lucy-den terminal and the phone) + OPENCLAW (steps 2, 4, lucyosctl verbs only)
**Scope:** runtime on Lucy-den; evidence file `.lucy/planning/lucyos-total-recovery/evidence/e2e_openclaw_<date>.md`
**Do not touch:** code; OpenClaw never originates `APPROVE`/`DENY`: it only forwards the owner's own WhatsApp message unchanged; no raw `aion`, `git` or SQL from OpenClaw
**Dependencies:** PR #89 merged (done); `fable/router-strict-approvals` merged; planning branch merged; `git pull && ./aion boot` on Lucy-den; owner then sends OpenClaw "pulled"

## Steps
1. OWNER, Lucy-den terminal: `./aion approval-add 'E2E probe' --why test --reversibility full --prepared yes --resumes nothing`. The first line of the output is `APPROVAL A-<n>`; that is the ID.
2. OPENCLAW: forward the owner's next three WhatsApp messages, each via `LUCYOS_PRINCIPAL=<owner sender id> scripts/lucyosctl whatsapp "<message unchanged>"`, and send each reply back to the owner.
3. OWNER, phone: send `status`, then `APPROVE A-<n>`, then `don't approve A-<n>` (must reply "Nothing was decided" or "already approved", and must not change anything), then `tasks`.
4. OPENCLAW: `scripts/lucyosctl whatsapp "why A-<n>"` with `LUCYOS_PRINCIPAL=openclaw-routine`; report the `Status:` line (must be APPROVED).
5. OWNER, Lucy-den terminal:
   ```
   ./aion audit-export --out /tmp/e2e.json && ./aion audit-verify /tmp/e2e.json
   grep -c '"kind": "openclaw"' /tmp/e2e.json
   grep -c '"actor": "openclaw:' /tmp/e2e.json
   ```
   Paste the three results into the evidence file with the sender id masked (e.g. `+91XXXXXX7890`). Never paste the full number or the JSON file.

## Acceptance tests
- `why A-<n>` reports `Status: APPROVED`
- the loose `don't approve` message changed nothing (reply text quoted in evidence)
- `audit-verify` passes; at least 4 `openclaw` events; the decision's actor is `openclaw:<masked id>`
- `./aion scan .lucy/planning/lucyos-total-recovery/evidence` is clean

**Security / rollback:** the probe approval resumes nothing. OpenClaw decides nothing itself. Revert = stop forwarding; the probe row stays as harmless history.
**Deliverables:** evidence file; EV-L2 key added to `evidence/EVIDENCE_INDEX.md`
**Stop conditions:** any reply shows an approval decided by a message that was not the exact `APPROVE <ID>` form -> stop, record, report to Fable. `lucyosctl whatsapp` refused -> record the exact error and stop.
**Fable review required?** NO (evidence only)
