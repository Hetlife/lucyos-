# TR-2-06 — Encrypted secrets escrow backup (`aion secrets-backup`)

**STATUS: OPEN.**
**Why:** `aion backup` deliberately excludes `private_state/`, and `07_DEPLOYMENT_MAC_MIGRATION.md` says the secrets file is "backed up separately and encrypted", but no tool does that. A disk loss today loses every secret. PR #2 had a gpg script for this (`git show a968606:scripts/backup_secrets.sh`); port the idea, not the gpg dependency.
**Current evidence:** `aion_core/backup.py` (`encrypt_bytes`/`decrypt_bytes`, stdlib encrypt-then-MAC; `create()` excludes private_state at line ~120); `18_AUDIT_20261004.md` §6.
**Executor:** CLAUDE_CODE (Sonnet S-IMPL)
**Scope:** `aion_core/backup.py`: `secrets_backup(passphrase) -> Path` (tar.gz of `<AION_HOME>/private_state` → `encrypt_bytes` → `<AION_HOME>/BACKUPS/secrets/secrets-<UTC>.tar.gz.enc`, mode 0600, keep 7) and `secrets_verify(passphrase, path=None) -> dict` (decrypt and list members to a temp dir; never print contents); `aion_core/cli.py`: `aion secrets-backup [--verify-only]`. The passphrase comes from `LUCYOS_SECRETS_ESCROW_PASSPHRASE` or a hidden `getpass` prompt, **never** from the secret store (it must not live on the same disk); tests; one line in `docs/OPERATIONS.md`.
**Do not touch:** protected paths; `scripts/maintenance.sh` (this is NOT run unattended, by design); no `gpg` or other dependency; no secret value in logs, events, or test output
**Dependencies:** none

## Steps
1. Tests first: round trip (a temp AION_HOME with a fake `private_state/secrets.env` → backup → verify lists `secrets.env`); wrong passphrase → BackupError, exit 1, no plaintext on disk; empty passphrase refused; file mode 0600; prune keeps 7; output and `events` rows never contain the fake secret value.
2. Build the tar in memory (`io.BytesIO`) and write only ciphertext. Do **not** copy `create()`'s current pattern: it writes the plaintext tar to `dest` and then overwrites it, contradicting its own docstring (ISSUE-048). Fix `create()` the same way in this PR when a passphrase is configured. Test: patch `tarfile.open` and assert that no path argument is given when encrypting.
3. Implement by reusing `encrypt_bytes`/`decrypt_bytes`/`_prune` (a twin of `_prune` with its own glob is acceptable only if `_prune` cannot take a pattern).
4. Document: "copy the `.enc` file off this machine (USB or scp over the tailnet); keep the passphrase in your head or a password manager."
