wants real public access, the correct answer is a domain + a reverse proxy with

8. STRUCTURE FOR FUTURE EXPANSION — follow these conventions
--------------------------------------------------------------------------------

The system is already organised for growth. Preserve these patterns; do not
invent parallel ones.

ONE FOLDER PER BUSINESS
  PROJECTS/<business-name>/ holds that business's plan, task packets, state and
  handoff files. PROJECTS/sevaa-sales-os/ is the worked example: it has
  AION_TASK_QUEUE.md (task packets with allowed files, test command, success and
  failure conditions, merge order), MACHINE_HANDOFF.json (the machine-readable
  current state), and bundles/ (prepared changes). A second business gets the
  same shape, not a new invention.

ADDING A REVENUE MODULE
  aion_core/sevaa.py is the reference integration contract: signed webhooks in,
  approvals out, revenue rows recorded as ACTUAL only when real. A new module
  copies that shape — its own aion_core/<module>.py, its own tests, an explicit
  allow-list of fields that may cross the boundary, and a forbidden-key list
  asserted by a test against real serialized bytes, not just return values.

DATABASE CHANGES ARE ADDITIVE ONLY
  aion_core/db.py has an _ADDED_COLUMNS dict and a _migrate() function. New
  columns are added there. Never drop a column, never rename one, never write a
  destructive migration. Existing brains in the field must keep opening.

NEW COMMANDS ARE DETERMINISTIC FIRST
  A new WhatsApp/phone command goes into aion_core/router.py as a regex plus
  SQL, so it answers with no model call and works when every provider is down.
  Only escalate to a model if the answer genuinely cannot be computed.

STDLIB ONLY
  aion_core/ imports nothing outside the Python standard library. If you think
  you need a dependency, you have almost certainly not thought hard enough. This
  is why the system installs on a bare box in seconds and cannot break from a
  supply-chain update.

EVERY NEW RULE GETS A TEST
  There are 204 tests because every guarantee in the README is enforced by one.
  A new guarantee without a test is not a guarantee.

DOCS ARE GENERATED, NOT HAND-MAINTAINED
  `aion sync-docs` regenerates the derived documentation. NOTEBOOK.md is the one
  hand-written surface: anyone (owner, another AI, this machine) appends [BUG],
  [TASK], [FACT], [FIX], [NOTE], [QUESTION] or [HANDOFF] entries, and
  `aion notebook sync` turns each into real state exactly once.
